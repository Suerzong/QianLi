## 为什么必须记录"夹爪最低点"而不是 TCP

碰到障碍物的永远是**夹爪几何最低点**；TCP 是爪口里的抓取中心，
它相对最低点的高度**随姿态剧烈变化**。实测扫描（`tcp_offset_sweep.py`）：

| 工具轴偏离竖直 | TCP − 夹爪最低点 |
|---|---|
| 7°（几乎竖直） | +5.1 mm |
| 22° | +7.6 mm |
| 52° | +11.4 mm |
| 68° | +12.5 mm |
| 83° | +46 mm |
| 90°（横着） | **+100.6 mm** |

跨度 **95.5 mm**。所以"让爪子碰桌子、读 TCP 的 Z"读数会随姿态漂移几十毫米 ——
第一次用 TCP 测时 6 个点就差了 31 mm，换成最低点后只差 1.5 mm。

另外 TCP 还沿工具轴横向偏 7 mm，倾斜 θ 时额外贡献 `7·sin(θ)` 的高度差。

## 垫台（机械臂下面那个台子）高度反推

不方便直接量，用模型反推：

```
base_link 各 visual 网格 Z 范围（base_link 坐标系）：
  base_so101_v2.stl                      -2.40 ~ +69.60 mm   ← 安装面
  base_motor_holder_so101_v1.stl        +35.70 ~ +67.10 mm
  waveshare_mounting_plate_so101_v2     +26.40 ~ +68.40 mm
  sts3215_03a_v1                        +24.30 ~ +63.90 mm

机械臂安装面（base_link 最低点）  =  -2.40 mm
实测桌面高度                      = -69.09 mm
────────────────────────────────────────────
垫台高度                          =  66.69 mm
```

> 注意取的是 **base_link 自身**的最低点，不是全机最低点：零位姿态下夹爪垂到
> −104 mm，那是悬空的末端，不是坐在垫台上的面。

旧值 **50 mm** 来自"最下端离桌面约 5cm"的估算 → 差 **+16.7 mm**。
`digital_twin.py` 里的底座几何本来就是 `BASE_BOTTOM - TABLE_Z` 推出来的，
所以把 `TABLE_Z` 改成实测值之后，垫台自动变成 66.69 mm。

### 独立交叉验证

渲染整机场景时（`render_scene.py`），当时的静止姿态正好是"夹爪搁在桌面上"：

| | 值 |
|---|---|
| 模型 FK 算出的夹爪最低点 | **−69.6 mm** |
| 实测桌面 | **−69.1 mm** |
| 差 | **0.6 mm**（在实测残差 RMS 0.469 / 最大 0.76 mm 之内） |

**FK 模型 ↔ 手拖 6 个接触点 ↔ 另一时刻的静止姿态**，三方在亚毫米级一致。
如果"夹爪最低点"或桌面高度任一有错，这里不可能对齐。

## 复现

```bash
# 1) 采集（网页前端，拖动机械臂让夹爪任意部位轻触桌面）
~/mj/bin/python table_limit_gui.py --port 8100 --margin-mm 8
#    浏览器打开 http://<虚拟机IP>:8100 ，每触一处点一次「记录接触点」

# 2) 求解（可离线回放 JSON，不必重拖）
~/mj/bin/python table_limit_solve.py --marks /tmp/table_marks.json \
    --margin-mm 8 --out /tmp/table_limit.txt

# 3) 查看某个姿态下最低点与 TCP 的差
~/mj/bin/python gripper_clearance.py
~/mj/bin/python tcp_offset_sweep.py      # 扫描全姿态范围
```

## 下游怎么用

`/tmp/table_limit.txt` 里的 `safe_z_min` 应当作为抓取脚本的**硬闸门**：
任何 TCP 目标高度低于它都直接拒绝。

注意闸门是加在 **TCP** 上的，而安全判据是**夹爪最低点**。两者关系随姿态变化，
所以闸门应当写成：

```
safe_tcp_z >= table_z + (TCP 相对最低点的高度) + margin
```

其中那个高度可以用 `gripper_model.GripperModel.lowest_point()` 按当前关节角实时算。
只在工具接近竖直（< 15°）时，才能用简化的固定值（约 +5 mm）。
