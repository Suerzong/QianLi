# 桌面标定结果（2026-10-06 实测）

> 由 `table_limit_gui.py` 采集、`table_limit_solve.py` 求解。
> **记录的是"夹爪几何最低点"，不是 TCP** —— 原因见下。

## 结果

| 项 | 值 |
|---|---|
| **桌面高度** | **−69.09 mm**（base_link 下） |
| 平面法向 | (0.0030, −0.0019, 0.99999) |
| 平面倾角 | **0.202°**（相对水平） |
| 拟合残差 | **RMS 0.469 mm**，最大 0.760 mm |
| 采样点数 / 范围 | 6 点 / 239 × 353 mm |
| 采样时夹爪倾角 | 0.2° ~ 3.6° |

单点残差(mm)：`[-0.76, 0.61, -0.06, -0.25, -0.07, 0.54]`

### 与旧假设对比

```
旧假设 board_z = -49.4 mm   （来自 2026-10-05 那轮两点标定）
实测    桌面   = -69.1 mm
相差           = +19.7 mm
```

**旧假设比真实桌面高了将近 2 cm。** 旧值出自那轮"两个内角点 Z 相差 9.5mm"
的两点标定，本身不可信，现已被实测取代。

## 为什么必须记录"夹爪最低点"而不是 TCP

碰到障碍物的永远是**夹爪几何最低点**；TCP 是爪口里的抓取中心，
它相对最低点的高度**随姿态剧烈变化**。实测扫描（`tcp_offset_sweep.py`）：

| 工具轴偏离竖直 | TCP − 夹爪最低点 |
|---|---|
| 7°（几乎竖直） | +5.1 mm |
| 22° | +7.6 mm |
| 52° | +11.4 mm |
| 68° | +12.5 mm |
| 83° | +46 mm |
| 90°（横着） | **+100.6 mm** |

跨度 **95.5 mm**。所以"让爪子碰桌子、读 TCP 的 Z"读数会随姿态漂移几十毫米 ——
第一次用 TCP 测时 6 个点就差了 31 mm，换成最低点后只差 1.5 mm。

另外 TCP 还沿工具轴横向偏 7 mm，倾斜 θ 时额外贡献 `7·sin(θ)` 的高度差。

## 垫台（机械臂下面那个台子）高度反推

  sts3215_03a_v1                        +24.30 ~ +63.90 mm

机械臂安装面（base_link 最低点）  =  -2.40 mm
实测桌面高度                      = -69.09 mm
────────────────────────────────────────────
垫台高度                          =  66.69 mm
```

> 注意取的是 **base_link 自身**的最低点，不是全机最低点：零位姿态下夹爪垂到
> −104 mm，那是悬空的末端，不是坐在垫台上的面。

旧值 **50 mm** 来自"最下端离桌面约 5cm"的估算 → 差 **+16.7 mm**。
`digital_twin.py` 里的底座几何本来就是 `BASE_BOTTOM - TABLE_Z` 推出来的，
所以把 `TABLE_Z` 改成实测值之后，垫台自动变成 66.69 mm。

### 独立交叉验证

渲染整机场景时（`render_scene.py`），当时的静止姿态正好是"夹爪搁在桌面上"：

| | 值 |
|---|---|
| 模型 FK 算出的夹爪最低点 | **−69.6 mm** |
| 实测桌面 | **−69.1 mm** |
| 差 | **0.6 mm**（在实测残差 RMS 0.469 / 最大 0.76 mm 之内） |

**FK 模型 ↔ 手拖 6 个接触点 ↔ 另一时刻的静止姿态**，三方在亚毫米级一致。
如果"夹爪最低点"或桌面高度任一有错，这里不可能对齐。

## ⚠️ 陷阱：夹爪开合角会让"最低点"移动 6.25 mm

这是 2026-10-06 现场发现的，**标定流程原本漏掉了这个变量**。

现场现象：夹爪贴在桌面上（人工确认），但模型算出最低点在桌面**下方 5.7 mm**。
排查发现该姿态最低点落在 `moving_jaw` 上，而标定时 6 个点的最低点都在
`gripper_link` 上 —— **参考点换了**。

`jaw_angle_sweep.py` 在固定臂姿态下扫夹爪角：

| 夹爪角 | 最低点 z | 最低点部件 |
|---|---|---|
| −7°（几乎闭合） | −68.29 mm | moving_jaw |
| **+14°** | **−74.12 mm** ← 最低 | moving_jaw |
| +35° | −69.20 mm | moving_jaw |
| **+43° 以上** | **−67.86 mm**（恒定） | **gripper_link** |

**跨度 6.25 mm**，与现场那 5.7 mm 吻合。

原因：夹爪张开超过约 43° 后，活动爪收进去，**固定爪**成为最低点；而闭合
过程中活动爪甩到固定爪**下面** 6 mm。

### 后果与对策

| 用途 | 该用哪个口径 |
|---|---|
| **桌面标定** | 必须**锁定夹爪角**（本次是张开，1.745 rad），或逐点归一化到基准角 |
| **安全判定** | 必须用**当前实际夹爪角**——因为物理上真的会撞 |

所以本次实测的 `table_z = −69.09 mm` 是"**夹爪张开时**固定爪贴桌面"的高度。
用别的开合状态去比较会差最多 6 mm。**下次标定必须把夹爪角记录下来。**

## 安全判定：基于模型，不靠肉眼

`arm_safety_monitor.py` 实时扫**全部 link** 的网格（不只夹爪 —— 肘部、前臂
在低姿态下也可能先碰）算整机最低点：

```
clearance = min(所有臂 link 的最低 z) − 桌面 z
safe      = clearance >= margin
```

现场验证（你手拖机械臂时）：

```
⛔ UNSAFE  净空   +2.44mm  [gripper_link]  TCP z=-64.0mm
✅ SAFE    净空  +15.67mm  [gripper_link]  TCP z=-50.3mm
⛔ UNSAFE  净空   -0.56mm  [gripper_link]  TCP z=-66.3mm   ← 爪子搁在桌面上
```

最后一行是关键证据：**爪子实际搁在桌面上时，模型给出 −0.56 mm，而桌面拟合
残差是 RMS 0.469 mm —— 两者在误差范围内吻合。** 这套几何在真实接触条件下
准到亚毫米，可以放心当安全闸门用。

输出：`/arm_safety`（JSON）、`/safety_markers`（RViz 里的小球 + 到桌面的
竖线 + SAFE/UNSAFE 文字）。

用于规划时，`margin` 建议 5~10 mm；用于"静止放置"判断时可以放到 1 mm。

    --margin-mm 8 --out /tmp/table_limit.txt

# 3) 查看某个姿态下最低点与 TCP 的差
~/mj/bin/python gripper_clearance.py
~/mj/bin/python tcp_offset_sweep.py      # 扫描全姿态范围
```

## 下游怎么用

`/tmp/table_limit.txt` 里的 `safe_z_min` 应当作为抓取脚本的**硬闸门**：
任何 TCP 目标高度低于它都直接拒绝。

注意闸门是加在 **TCP** 上的，而安全判据是**夹爪最低点**。两者关系随姿态变化，
所以闸门应当写成：

```
safe_tcp_z >= table_z + (TCP 相对最低点的高度) + margin
```

其中那个高度可以用 `gripper_model.GripperModel.lowest_point()` 按当前关节角实时算。
只在工具接近竖直（< 15°）时，才能用简化的固定值（约 +5 mm）。
